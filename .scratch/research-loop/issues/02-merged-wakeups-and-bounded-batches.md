# 02 合并唤醒与有界连续批处理

**What to build:** 连续快速投递能够合并唤醒信号，由一个处理实例按单轮上限持续消费，直到收件箱和待处理队列都得到处理结果；用户可以从状态和日志判断当前处理进度。

**Blocked by:** 01 处理轮次安全契约

**Status:** ready-for-agent

- [ ] 五条快速投递只形成一个正在运行的 agent 轮，后续唤醒合并为待处理标记，不产生重复并发写回。
- [ ] 单轮达到上限时，未处理收件项留在收件箱；当前轮结束后会自动继续，最终每条都获得唯一回执结果。
- [ ] 处理轮始终受单实例锁保护，锁占用时不会启动第二个 agent。
- [ ] 队列记录入列、合并、等待时长、阶段耗时、剩余收件项和研究任务数量。
- [ ] `STATE` 能显示当前阶段、最后错误、剩余收件项和待研究任务数量。
- [ ] 自动化测试验证快速投递、队列合并、批次继续和已有收件 HTTP 响应语义保持不变。
