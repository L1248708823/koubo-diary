# 捕捉端 UX 原型记录

这是一个可删除的临时原型，不是生产实现。

## 问题

这套提交手感，我愿不愿意在「灵感稍纵即逝」和「晚上冥想前连续倒几段」时每天用？

## 运行

在项目根目录执行：

```bash
python3 -m http.server 4173 --directory temp
```

然后分别打开：

- <http://localhost:4173/capture/index.html>：A · 极简投递
- <http://localhost:4173/capture/b.html>：B · 投递 + 在场感
- <http://localhost:4173/capture/c.html>：C · 主动作贴输入完成处

三页是独立 HTML5 页面，不共用同一页面骨架；页面底部的 A/B/C 仅用于原型间跳转。

## 结论（用户选定 B）

问题 5b 结论是采用 **B · 在场感**（`b.html`）作为捕捉端 v1 手感，不采用 A 的纯极简，也不采用 C 的输入框内角发送。

**保留的提交 affordance**
- 底部固定、全宽、高对比的「送进收件箱」
- 空内容时禁用但按钮始终占位，避免布局跳动
- 成功：清空 + 轻反馈 + 回焦，支持连续投递
- 失败：正文不丢，明确提示
- 成功后短时「撤销」（B 相对原提案的增强，值得进 v1）

**B 相对原提案多出来、也一并锁定的**
- 「今日已投 N 条」在场计数
- 可折叠的今日已投列表（只读回看，不在捕捉端改正文）
- 大字号输入卡，打开即聚焦；placeholder「说就行…」
- 不自研语音，继续系统语音输入法打进输入框

**分类**
- 继续留在处理端；捕捉端不选手动「日记 / 想法」

**明确不进 v1 捕捉端**
- C 式角上发送键（拇指目标偏小，文案也不如全宽按钮醒目）
- 按住说话 / 自动开麦
- 在手机上编辑已投正文或直接写日记

- AI 整理规则（保语气、去重复的边界）
- 日记 vs 想法的判定与写回
- 后台调研是否进第一版
