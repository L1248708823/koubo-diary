# 03 — 投递唤醒处理轮（假 agent 贯通）

**What to build:** 用户（或测试客户端）完成一次合法投递后，系统能唤醒（或等价触发）一轮处理编排；在假 agent 下跑通「收件箱条目 → 写回日记（及规则允许的想法）→ 验收 → 脚本清理该 inbox」。证明**上传不等于整理**，但**上传能叫醒整理**；与仅定时手动跑编排可区分（唤醒存在且可用）。仍不要求真 Claude 或真手机。

**Blocked by:** 01 — 处理编排全契约（假 agent）；02 — 收件接口：鉴权投递只进收件箱

**Status:** done

- [x] 合法投递后存在可观测的唤醒/触发，使处理轮在无需人工再点「处理」的情况下启动（测试可加速或同步化等待）
- [x] 贯通后：对应口播的写回出现在日记侧（假 agent 行为），该收件箱条目按成功路径被脚本删除
- [x] 投递响应仍只表示 delivered，不声称已整理
- [x] 唤醒与可能的并发编排启动被单实例锁串行，不双开两轮写同一 vault（可用测试夹具验证锁行为）
- [x] 自动化或脚本化验收覆盖「投递 → 唤醒 → 成功清理 inbox」主路径
