# 捕捉端 UX · 设计说明（问题 5b 原型配套）

> 抛开用。回答「这套手感我愿不愿意在灵感稍纵即逝和晚上冥想前连续倒几段时每天用？」  
> 可点原型：`temp/capture/index.html`（A）、`temp/capture/b.html`（B）、`temp/capture/c.html`（C）
> 配套 grill 共识见下文；代码不当生产。

## 要回答的问题

问题 5b：捕捉页的提交手感与信息架构，能否同时扛住：

1. **灵感稍纵即逝**：单手、约五秒，打开 → 说 → 送进收件箱  
2. **冥想前连倒**：同一 UI 连续多段，不切换上下文

不在本轮回答：处理端触发、AI 整理规则、日记 vs 想法分类算法、真 GitHub 写入。

## 三变体立场（必须吵起来的那一刀）

### A · 极简投递

捕捉页是管道，不是工作台。大输入框 + 底部全宽高对比「送进收件箱」。成功：清空、轻提示「已投递」、立刻回焦。无历史、无撤销。用来压测：五秒灵感是否够干净，以及没有后悔药时敢不敢用力点。

### B · 投递 + 在场感

输入仍是主角；顶部露出「今日已投 N 条」，默认可展开看本地 mock 列表。成功后新条短暂可感，并提供数秒「撤销」。用来压测：连倒时有没有「东西确实进去了」的安心，以及有后悔药时点按钮的力气会不会变。

### C · 主动作贴输入完成处

取消大底栏主按钮。输入区右下（或键盘逻辑上方）放聊天式发送键；底区只承担次要信息或失败提示。用来压测：系统语音键盘顶起时，大底栏是不是真别扭，聊天发送键是否更接「说完就丢」。

## 跨变体共享规则

1. **打开即聚焦**输入框；placeholder 用「说就行…」一类低压力文案。  
2. **主路径文案**用 glossary：口播、收件箱、送进收件箱、已投递。避免「录音 / 语音笔记 / temp」。  
3. **空内容不可提交**：主控件 disabled，但占位不导致布局跳动（A 的底栏始终在；C 的发送键始终在，仅禁用）。  
4. **成功**：清输入、短反馈、回焦，服务连续捕捉。  
5. **失败**：**绝不**清输入；展示原因（mock：网络/权限等一句人话）。由「下次提交强制失败」开关触发一次后自动复位。  
6. **草稿**：`variant` 切换不丢未送出文本；已投递列表三变体共用同一 mock 源。  
7. **存储**：`localStorage` 即可，键名带 `prototype-capture` 前缀，可一键清空。  
8. **主题**：`data-theme`，默认 dark，右上可切。  
9. **原型页面**：A/B/C 各自是独立 HTML5 页面，通过原型专用浮动条互相跳转；不共用同一页面骨架。
10. **不做**：分类、真 GitHub、粘贴按钮、按住说话、自动麦克风、处理端任何逻辑。

## 变体 B 专属

- 成功后约 5s 内可「撤销」上一条（仅 mock 列表删除 + 可选把文本填回输入框，便于连倒误触）。  
- 今日计数与列表仅本地、按日 key；展开后可扫最近几条，不是工作台。  
- 撤销与在场感绑在同一心理账户，不搬到 A/C。

## 变体 C 专属

- 主按钮 = 输入容器内右下发送键（图标或「送出」短词），大拇指在输入结束附近。  
- 无底部全宽主按钮；失败提示可用顶部 toast 或输入区下方一行，避免再造一条高对比底栏把 C 变回 A。

## 真机怎么验

1. 手机浏览器分别打开 `temp/capture/index.html`、`temp/capture/b.html`、`temp/capture/c.html`（或本地静态服）。可选「添加到主屏幕」。
2. **暗色**下先走变体 A：五秒口播一条，体会有无撤销时的点按力度。  
3. 同一段连倒 3～5 条，切到 B：看计数与撤销是否让你更敢送或更拖沓。  
4. 调起系统语音输入法，切到 C：键盘顶起时发送键是否仍够得到、是否比 A 的底栏更顺。  
5. 打开「下次失败」，任意变体提交一次：正文必须还在，原因必须看见。  
6. 亮色只做可读性抽查；**愿不愿意每天用**以暗色 + 真语音为准。
