# 01 — 处理编排全契约（假 agent）

**What to build:** 在临时 vault 上能完整跑一轮处理编排（不接真 Claude、不接真 GitHub）：收件箱有口播时，假 agent 写出日记（及可选想法）与合法回执后，机械验收通过，**由脚本删除**对应收件箱条目，工作树呈现「正文在、该 inbox 不在」；收件箱为空则早退且不调 agent。同一套编排还须守住失败网：验收失败或不完整回执时**不删**收件箱；未授权的 inbox 删除视为失败并尽量恢复；同条失败次数到顶进入**隔离区**且不再当普通待处理；单轮处理条数有上限；锁已被占则立即退出；白名单外路径变更则整轮失败、不提交危险变更。从外部只通过目录、回执与轮次结果验证，不断言 agent 内部实现。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 空收件箱运行一轮：早退、不调用 agent、不删除隔离区外无关文件
- [x] 假 agent 对一条 inbox 声明 done 且工作树已有对应日记（及若声明则有想法）：验收通过后该 inbox 文件由编排删除，写回文件仍在
- [x] done 但缺声明的 diary（或声明了 idea 却不存在）：验收失败，inbox 仍在
- [x] 工作树出现回执未授权的 inbox 删除：轮次失败，inbox 尽量恢复存在
- [x] 失败累计至配置阈值（默认 3）：条目进入隔离区，后续普通待处理列表不再包含它
- [x] 收件箱超过单轮上限（默认 10）：本轮最多处理上限条，其余留守收件箱
- [x] 白名单外路径出现变更：整轮失败，不把该变更当成成功提交内容
- [x] 锁已被占用：立即退出，不启动 agent
- [x] 自动化测试覆盖上述对外行为（临时 vault + 可注入的假 agent / 锁 / git 依赖）
