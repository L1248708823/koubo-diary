# Spec: 处理环失败可见性与研究写回契约

Status: ready-for-agent
Feature slug: `processor-reliability-contract`
Sources: `CONTEXT.md`、ADR-0004、ADR-0005、ADR-0006、ADR-0007、现有处理环与研究环规格、真实 vault 审查结论

## Problem Statement

处理环已经具备收件、日记和想法写回能力，但若文件系统、Git、研究 runner 或状态写回发生异常，部分底层函数会返回空值、默认值或尽力而为结果。这样会把权限错误、Git 状态读取失败、状态文件写入失败和恢复失败伪装成空队列、缺文件或普通研究阻塞。

真实测试 vault 已出现明确的状态矛盾：`STATE.md` 报告成功且研究待处理为 0，研究任务记录却存在 3 个 `blocked` 任务；一份研究文件不是合法完成简报，日记还引用了不存在的研究简报。当前工作区已有针对研究状态和简报写回的未提交修复，但全量测试尚未恢复全绿，研究链接验收仍未完成。

用户需要在外部来源不可用时看到明确的阻塞状态，在程序错误、权限错误和恢复失败时看到真实失败原因，并确保脚本不会因 agent 的不完整写回而删除原始收件项。

## Solution

收紧处理环的错误分类和状态写回：只有明确可接受的缺失文件、锁竞争和幂等清理可以返回空值；权限、解析、Git、快照、恢复和状态写回失败必须被记录并向当前处理轮报告。外部研究来源不可用可以进入 `blocked` 或 `partial`，但任务记录、来源笔记和 `STATE` 必须保持一致。

研究简报只有在路径、frontmatter、任务问题、证据章节、来源双链、来源状态和完成状态全部验收后才可标记 `complete`。本轮实际变更的日记和想法中出现研究链接时，验收必须确认目标是存在且合法的顶层研究简报。真实 vault 的历史残留只做只读审计，不自动删除或迁移。

## User Stories

1. As a 使用者, I want 收件箱目录读取失败时看到处理失败, so that权限问题不会被误判为空队列。
2. As a 使用者, I want Git 状态读取失败时处理环停止, so that脚本不会在未知变更下继续验收或发布。
3. As a 使用者, I want 原始收件项读取失败时保留原文并报告原因, so that重试计数不会被重置。
4. As a 使用者, I want 处理状态写入失败时看到错误, so thatSTATE.md 不会长期显示过期状态。
5. As a 使用者, I want agent 变更恢复失败时看到恢复失败, so that越权文件不会在无提示的情况下残留。
6. As a 使用者, I want 研究来源超时或不可访问时任务进入 blocked, so that我不会把研究失败误认为完成。
7. As a 使用者, I want 证据不足时任务进入 partial, so that已核验内容可以保留而未完成部分继续可见。
8. As a 使用者, I want 研究任务仍未完成时 STATE 的待处理数量准确, so that我能知道是否还有后续工作。
9. As a 使用者, I want 研究简报缺少合法 frontmatter 时不能进入 complete, so that无效文件不会成为长期结论。
10. As a 使用者, I want 日记或想法引用不存在的研究简报时处理轮失败, so that双链不会制造死链接。
11. As a 使用者, I want 研究失败时原始记录、日记和想法保留, so that外部服务失败不会造成内容丢失。
12. As a 使用者, I want 研究来源状态和任务状态同步, so that同一任务不会在不同文件中显示冲突结果。
13. As a 使用者, I want 研究完成后关闭 needs_research, so that已完成任务不会被无限重试。
14. As a 使用者, I want 研究失败后保留 needs_research, so that下一轮仍有机会继续。
15. As a 开发者, I want 缺失文件和真正 I/O 错误被区分, so that兼容行为不会掩盖程序问题。
16. As a 开发者, I want 失败路径的恢复结果进入处理轮结果, so that调用方能决定是否停止或告警。
17. As a 开发者, I want 本地 vault 和真实 Git vault 对工作区错误使用一致语义, so that测试不会遗漏生产风险。
18. As a 开发者, I want 研究 runner 的未知异常保留原始错误信息, so that程序 bug 不会伪装成来源阻塞。
19. As a 开发者, I want 研究链接验收只检查本轮实际变更, so that历史 vault 问题不会阻塞当前新内容。
20. As a 开发者, I want 失败状态不会触发无限自动重试, so that网络或模型故障不会持续消耗资源。
21. As a 开发者, I want 无研究 runner 时仍能准确报告未完成任务, so that探测模式不会隐藏研究积压。
22. As a 开发者, I want 真实 Codex 研究只作为人工 smoke test, so that自动化测试不依赖模型和网络稳定性。

## Implementation Decisions

### 错误分类

处理环统一使用以下判断：

- 明确不存在且业务允许首次创建的文件，可以返回空结果。
- 并发锁已存在，可以返回 `locked`，并尽量读取锁持有信息。
- 幂等清理时目标已经消失，可以视为清理完成。
- 权限、解析、Git 命令、快照、写入、恢复和状态文件错误不能转成空数组、`false`、`null` 或默认计数。
- 外部研究来源不可用、超时、证据不足和研究简报不完整分别进入 `blocked` 或 `partial`，并保存 `last_error`。
- 未知程序错误保留原始错误信息并让当前处理轮失败；不能只凭 catch 位置把它归类成普通研究阻塞。

### 处理轮状态

- 内容整理成功且研究阶段完成时，轮次为 `success`。
- 内容整理已经写回，但研究阶段出现 `partial`、`blocked` 或写回验收失败时，轮次为 `failed`，已验收的日记和想法保留。
- `research_pending` 统计所有非 `complete` 任务，包括 `pending`、`running`、`partial` 和 `blocked`。
- 可重试数量单独统计 `pending`、`partial` 和 `blocked`，避免状态显示与队列唤醒混用。
- 研究 runner 缺失时，内容整理仍可完成，但状态必须明确表示研究任务未完成，不能伪装成研究成功。

### 工作区和恢复

- 本地快照和真实 Git 工作区在读取失败时都必须返回明确失败。
- Git 命令非零退出必须区分目标不存在、仓库错误和命令失败；命令失败不能直接执行删除恢复。
- 恢复路径失败必须进入处理轮结果和日志；处理环不能只保留最初的验收错误。
- 失败路径的状态、重试次数和隔离动作如果无法写回，必须报告写回失败，不把尽力而为当作成功。
- 真实 vault 中既有的非法嵌套 Yan帳、旧简报和死链接只做只读审计，本规格不自动迁移或删除。

### 研究写回

- 研究任务状态以 `research_status` 为准，`needs_research` 只作为候选和未完成信号。
- `complete` 必须同时满足研究问题、证据、来源、反方审查、未知点、日期、来源双链、来源状态和简报结构验收。
- `partial` 和 `blocked` 保留原始来源内容与 `needs_research: true`。
- 研究 runner 写出不完整文件后，可以保留已生成内容，但必须明确标记未完成，不能把 `completed_with_limits` 等非规范状态视为完成。
- 研究简报链接必须指向配置的顶层研究目录下一层 Markdown，并且文件真实存在。
- 只检查本轮被处理的日记和想法中的研究链接，历史未变更文件由独立审计处理。

### 提示词与机械验收

- 研究和内容整理 prompt 必须声明允许修改的对象、状态语义和失败处理方式。
- agent 不拥有删除收件项和提交 Git 的能力；脚本继续掌握删除、隔离、恢复和发布。
- prompt 负责指导模型，机械验收负责决定是否接受结果；两者不以自然语言互相替代。

## Testing Decisions

### 好测试的定义

测试只验证文件、状态、路径、回执、处理轮结果和资源所有权等外部行为。测试样例用于固定已确认的契约，不能替代真实业务边界审查。

### 主要验证 seam

- 以最高层处理轮注入临时 vault、假 agent、假 research runner、假工作区、锁和时钟。
- 以工作区 adapter 验证本地快照和真实 Git 错误的统一失败语义。
- 以研究阶段 seam 验证 `pending`、`partial`、`blocked`、`complete` 的转换和数量统计。
- 以研究写回验收 seam 验证非法简报、死链接、错误 task_id、缺少双链和来源状态不一致。
- 真实 Codex、网络超时和真实 vault 只执行人工 smoke test 与只读审计。

### 必须覆盖的失败场景

- 收件箱读取权限失败。
- 收件项读取失败和重试计数读取失败。
- Git status、Git cat-file、pull、push 和恢复命令失败。
- STATE、回执、研究任务状态和来源笔记写入失败。
- agent 修改或删除收件项，研究阶段修改收件项，恢复越权文件失败。
- 研究来源不可用、研究超时、简报不完整、来源链接不存在。
- 任务为 `partial` 或 `blocked` 时状态准确，且不会无限自动重试。

## Out of Scope

- 重写处理编排器的整体结构。
- 自动清理真实 vault 历史文件、非法嵌套目录或旧研究简报。
- 新增通知系统、研究权限 UI、全文搜索或多用户能力。
- 证明真实 Codex 的知识质量或网络可用性。
- 修改输入捕捉方式和语音识别能力。

## Further Notes

当前工作区已有研究状态和研究 runner 的未提交改动。实现前必须保留这些改动，先处理新增回归与旧断言的语义一致性，再逐步收紧错误传播。Windows 工作区还存在 LF/CRLF 转换提示，提交前需要单独核对换行格式。
