# 日记写回既有按日树，Yan帳 内容顶层分区且保持扁平

个人 vault 已有按日回顾习惯（`生活/日子一天天过去/年/月/日`），另建平行「口播日记」区会增加打开心智负担。Yan帳 统一承载 AI 处理后的长期内容，其中想法与研究简报分区，便于双链和后续扩展。

决定：

1. **日记**：成功处理的口播写回  
   `生活/日子一天天过去/YYYY/YYYY-MM/YYYY-MM-DD.md`  
   同一天合并进同一篇；新建月目录用规范名 `YYYY-MM`（无前导空格）；不写入 `吾志/`、`wolai-app/` 等旁支。
2. **Yan帳 想法**：扁平 `Yan帳/想法/YYYY-MM-DD-短标题.md`，**一条想法一个文件**；不按日/月大杂烩；标题冲突则改名新建，不自动合并进旧文件。日期使用收件项的捕捉日期，后续修改不改变文件名中的日期。
3. **Yan帳 研究**：扁平 `Yan帳/研究/短标题.md`，**一条研究任务一个文件**；简报保留来源、证据、不同观点、未知点和研究时间；不与想法正文合并。
4. **互链**：日记侧为时间戳 + 一句钩子 + `[[Yan帳/想法/…]]`；想法侧为轻整理全文 + 链回当日日记；研究简报链回来源日记或想法，来源侧保留研究简报链接。
5. **双轴语义（模型判，捕捉端不选手动分类）**
   - 想法轴：能否离开「今天」单独回看 → 是否建想法文件（宁可少抽）  
   - 待查轴：是否有未决认知缺口 → 内容整理阶段登记研究任务；独立研究 runner 再按证据契约处理，证据不足时保留待查状态（宁可少标）
   - 两轴可组合，非互斥。
6. **归档**：当前上线版本不对想法或研究简报做按年目录或到期自动搬迁；想法文件名使用捕捉日期前缀只为方便排序，不等于按年归档。库膨胀后再议 `_archive` 或 status。

配置上 `DIARY_DIR` 取日记树前缀（默认示例即上述路径），`IDEAS_DIR=Yan帳/想法`，`RESEARCH_DIR=Yan帳/研究`；白名单放行日记树子路径，想法和研究只放行各自目录下的一层 Markdown 文件。

## Considered Options

- 新建扁平 `日记/` 与历史树并存（实现更简单，增加切换负担，未采纳为 v1 主路径）
- 想法按年/月分桶或按日杂烩（削弱「离开今天」的实体感，未采纳）
- v1 即自动按年归档（链接与路径成本高、想法宜常青，推迟）
- 开放自由 tag 分类（易大杂烩；v1 仅保留待查等领域标记）
