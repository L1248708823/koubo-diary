# 03 待查候选与研究任务生命周期

**What to build:** 处理端能够把日记或想法中的 `needs_research` 候选转成可恢复的研究任务，并在内容整理验收后自动进入研究阶段，同时保留内容阶段与研究阶段的独立失败边界。

**Blocked by:** 01 处理轮次安全契约

**Status:** done

- [x] 纯日常口播只产生日记；想法轴和待查轴可以独立成立，也可以同时成立。
- [x] 待查候选保存来源日记或想法、原始问题、创建时间、更新时间和研究状态，至少支持 `pending`、`running`、`partial`、`blocked`、`complete`。
- [x] 研究问题来自原始口播或来源笔记；问题模糊时记录假设与边界，不擅自扩大主题。
- [x] 内容整理阶段验收成功后，研究阶段在同一处理锁内自动消费候选；研究失败不回滚已验收的日记、想法或成功收件项。
- [x] 同一来源与问题不会静默生成重复任务；已有任务更新时保留旧状态、变更时间和失败原因。
- [x] 使用可注入的确定性研究 runner 验证任务去重、状态推进、重试和剩余队列，外部网络不进入自动化测试。
