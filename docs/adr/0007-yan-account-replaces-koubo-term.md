# Yan帳 作为产品主题并替代口播命名

日期：2026-08-03

## 背景

项目早期使用「口播」描述产品和输入内容。随着产品主题确定为 Yan帳，继续把「口播」同时当作产品名、用户文案和原始输入类型，会让品牌、工作流实体和内容类型混在一起。

## 决定

1. `Yan帳` 是产品主题和用户可见总称，页面标题、帮助文案、领域说明使用 Yan帳。
2. 单条待处理的输入在领域模型中称为 `收件项`，其正文属于原始记录。它可以来自语音输入法，也可以来自其他捕捉方式，不把输入媒介写进核心实体名称。
3. `日记`、`想法`、`待查`、`研究任务`、`研究简报`和`回执`继续保持独立含义，不用 Yan帳 代替这些实体名称。
4. `Yan帳/想法` 与 `Yan帳/研究` 继续作为 vault 顶层的长期内容分区。品牌命名调整不改变既有目录边界、日记树和处理环职责。
5. 技术包名、仓库目录和环境变量是否改名不属于本决定；它们只有在产生实际维护收益时再单独处理。

## 取舍

- 全局继续使用「口播」会让用户看到的产品主题与项目定位不一致。
- 直接把每个内部实体都改称 Yan帳 会丢失收件项、日记和研究任务之间的责任边界。
- 使用 Yan帳 作为产品总称、使用收件项作为原始记录实体，可以同时满足品牌一致性和业务精确性。
