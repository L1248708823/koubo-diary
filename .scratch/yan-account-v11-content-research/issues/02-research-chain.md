# 02：待查到研究简报的完整链路

**What to build:** 把内容中的具体待查问题接入现有研究流程。日记和想法完成写回并通过验收后，研究任务自动继续执行，研究方式根据问题选择，最终维护研究状态、研究简报和来源关联。

**Blocked by:** 01：收件项到日记与想法关联。

**Status:** ready-for-human

- [x] 只有确实需要外部资料、事实核验、当前信息、方案比较、可行性判断或其他证据支持时才登记研究任务。
- [x] 已有知识和推理足够解决问题时不强行搜索或创建研究任务，用户明确要求调研、来源或核验时按要求处理。
- [x] 想法轴和待查轴可以同时成立，没有独立想法的具体问题可以直接关联源日记。
- [x] 日记写回并通过验收后自动接续研究，不要求用户再次发送日记或输入第二个触发词。
- [x] 研究可以处理技术、产品、生活和其他领域的问题，研究结构随问题调整，不强制固定章节、来源数量和搜索轮数。
- [x] 研究简报清楚区分事实、推断、建议和未知点，外部事实使用可核验来源，无法核验的内容明确标记限制。
- [x] 搜索时不使用中文网站作为信源，不编造来源、链接、作者、日期、数据和搜索结果。
- [x] 需要方案比较时默认提供至少三种真实可行方案，详细说明适用条件、优缺点、代价、风险和推荐理由；确实不足三种时说明原因。
- [x] 只有在争议、比较、较高风险或用户明确要求时主动加入反方观点，并说明反方对结论的影响。
- [x] 同一研究问题出现新资料时更新原任务和简报，问题目标或范围变化时创建新任务和新简报并建立关联。
- [x] 研究完成、部分完成或阻塞时状态与证据完成度一致，研究结果不自动把用户想法标记为已验证或已实现。
- [x] 独立 research 进程调用显式使用模型 `gpt-5.6-luna` 和思考程度 `max`。
